# KijaniKiosk Hardening Decisions Document

The security hardening for the KijaniKiosk staging environment was designed with a focus on protecting the payments service while keeping the system manageable and reproducible. The approach involved implementing multiple layers of protection through system service configuration files, all of which are stored in version control to ensure consistency across deployments. The team decided to restrict file system access by making system directories read-only and limiting write permissions to only the specific directories needed for application operation. Network isolation was also implemented to prevent the service from sending or receiving external traffic, which reduces the attack surface significantly. The service was stripped of all privileged capabilities to prevent privilege escalation, and system call filtering was applied to block dangerous operations that could be exploited. Additional measures included isolating temporary files, protecting kernel modules from being loaded, and restricting memory operations to prevent common attack vectors. The team also implemented user isolation to ensure the service cannot access other user resources, and file permissions were set to secure defaults. These decisions were validated using a security scoring tool, which confirmed the payments service achieved a score of 0.6, well within the safe threshold of 2.5. All these measures are automatically applied through the Ansible pipeline, eliminating manual intervention and reducing the risk of human error. The team acknowledges that while this configuration is comprehensive, it does not protect against application-level vulnerabilities, insider threats, or physical security breaches, and these risks are being addressed through separate initiatives.
